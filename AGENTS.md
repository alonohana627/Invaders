# Notes for coding agents

Invaders is a Space Invaders-style shooter built on GameLib
(https://github.com/alonohana627/GameLib, locally `C:\Users\user\GameLib`; a
separate repository). It is the third game of GameLib's ten-game run
(`GameLib/GAME_SUGGESTIONS/03-invaders.md` is its spec).

## Ground rules

- Consume GameLib only through its CMake targets (`GameLib::core`,
  `GameLib::app`, ...) and public headers (`<gamelib/...>`). Never copy GameLib
  sources into this repository or include its `src/` files. Use what GameLib
  offers (its `FEATURES.md` at the pinned commit) instead of rewriting it.
- GameLib is pinned by full commit hash in `CMakeLists.txt` (`GIT_TAG`,
  `GIT_SHALLOW FALSE`). Bump it only together with a row in
  `docs/GAMELIB_REVISION.md`. GameLib keeps no backwards compatibility.
- A generic mechanism this game needs goes into GameLib first (its own
  commit, tests and docs, following GameLib's `AGENTS.md` and
  `docs/EXTENDING_GAMELIB.md`), then this game re-pins to that commit and
  uses it. Mechanisms only this game has are recorded as P0 entries in
  GameLib's `FEATURE_SUGGESTIONS.md`, not here.
- Do not modify Snake, Tetris, Pong, Breakout or Asteroids from this
  repository's work.
- Every visual is generated by shaders (GameLib's built-in shapes or this
  game's `shaders/`). No image files. Every sound is synthesized with
  GameLib's synth.
- `src/game` (rules, formation, shields, the demo gunner) links only
  `GameLib::core` and `GameLib::ai`: no window, GPU, audio or clock;
  deterministic for a seed and the inputs. Presentation, menus, sounds and
  settings live in `src/app`.
- **Games have no unit tests**: no test executables, no `GameLib::testing`.
  The only CTest entries are smoke runs of the real game (`smoke/`): hidden
  window, validation layer required, a fixed number of frames, driven by the
  demo gunner. They enforce zero Vulkan validation messages.
- Zero compiler warnings, zero shader warnings (glslc `-Werror`), zero
  validation messages.
- Small Conventional Commits (`feat(game):`, `feat(app):`, `build:`, `docs:`)
  after each step that builds and runs. Stage files explicitly; never commit
  build output. Never rewrite history. Push `main` to origin after each
  commit once the repository is published.
- `FEATURES.md` lists what the game does today, verified by running it;
  update it in the same commit as each feature; never list planned work.
- Run the game and look at it after every visual change (GameLib's smoke
  switches plus the `win32-game-window-automation` skill for screenshots).
  Do not drive F11 in automated runs: fullscreen takes over the monitor.

## Skill suggestions

Keep `SKILL_SUGGESTIONS.md` up to date: at the start of a session list
`~/.claude/skills/` and move newly installed skills to "Already installed";
add or sharpen an entry (kebab-case name, one paragraph, a "Why") whenever a
task would have gone better with a missing skill. Mention changes in one line.

## Layout

```text
CMakeLists.txt, CMakePresets.json   project, GameLib pin, presets
src/          the game
shaders/      the game's own fragment shaders
smoke/        CTest smoke runs
docs/GAMELIB_REVISION.md   the GameLib commit each change was validated with
```

## Commands

```powershell
cmake --preset debug           # configure (fetches GameLib from GitHub at the pinned commit)
cmake --build --preset debug
ctest --preset debug           # smoke runs (validation layer required)
build/debug/bin/invaders.exe   # play
```
